# T3: does `cao plugin validate` admit an over-limit skill?

**Task:** [`tasks.md` T3](tasks.md) · **Date:** 2026-11-01
**Worktree HEAD:** `27311798` (`git rev-parse --short=8 HEAD`)
**Settles:** `P-6` · **Evidence for:** Requirements 2.3, 2.4, 2.7, 2.11, 4.8; correctness property P2; `design.md § Testing strategy` item 1.

## Verdict

**`P-6` is now OBSERVED: `cao plugin validate` admits a skill whose `description` is 2000 characters and a skill whose body is 600 lines, reporting `"loadable": true`, `"findings": []` and exit 0, so no requirement criterion has to change.**

Requirement 2.3's claim (CAO checks a skill only for non-blank `name`/`description` and folder-equals-`name`) holds for the two length limits measured here. Requirement 2.7's "UNLESS T3 has settled it" branch now applies: the `Audit_Skill` may cite this report instead of marking the behaviour as inferred.

That cause is inferred from the directory names and was not traced in the code.

## Defects T3 told me to watch for

1. **Reporting the expected answer.** The answer matched the inference, and the folder-mismatch control (step 8) shows that a rejection would have been visible.
2. **Folder-name confound.** Folder equals `name` in both skills (step 2), and both appear in `skills[]` (step 5).
3. **Gate unset.** The gate was on for steps 3 to 5 and 7 to 8, and a known-good package validated in the same session (step 7). The unset run (step 6) emits no JSON; real runs emit JSON with a `loadable` key.
4. **Fixture location.** Temp directory only; nothing under `test/agent_plugins/fixtures/`.
5. **Hand-written lengths.** Both were generated and measured before validation (step 2).
6. **Clean-tree check.** The scope check compares against the stamp snapshot, not `git status --porcelain`.

## What this does and does not settle

- **Settled:** the 1024-character description limit and the 500-line body limit are not enforced by `cao plugin validate` at `27311798`. This is the P2 premise: `Audit_Skill` would flag what CAO reports clean.
- **Not tested:** the Agent Skills name regex and the 64-character name bound. T3 does not ask for them, and Requirement 2.3 also claims CAO does not enforce those. They remain inferred from `models/skill.py:6-19`, which checks only that `name` and `description` are non-blank.
- **Not tested:** Requirement 4.8's open caveat, whether `validate_plugin` can exit 1 with no JSON and no refusal text on a bad path. Step 6 shows the refusal text is present in the unset-gate case, which is what a wrapper should report.
- **Not checked:** whether the run wrote anywhere outside `CAO_HOME_DIR` and the fixture directory.
- **No lasting test.** As `design.md § Testing strategy` item 1 states, this experiment leaves no repository test; the fixtures live only in `/tmp`.
